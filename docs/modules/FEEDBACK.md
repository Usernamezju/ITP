# 用户反馈

顾客端顶栏头像按钮左侧是「反馈」入口：桌面端显示图标加文字，手机端只留
图标，但保持 44×44 的点击区域，不挤压「新建资产」和头像按钮。点击打开
原生 `<dialog>`：桌面端为居中卡片，760px 以下变成贴底抽屉。

## 提交流程

表单包含三项：反馈类型（功能建议 / 问题反馈 / 界面体验 / 其他，单选）、
反馈内容（必填，5–1000 字，带实时字数）、联系方式（选填，≤80 字，登录时
用账号已有的手机号预填，可改）。提交后表单替换为成功状态（「反馈已提交」
及是否关联账号），可以「再提一条」或直接关闭；失败时保留已输入内容，并在
表单内显示服务端返回的中文原因（长度不合规、限流、数据库忙等）。

`POST /api/feedback` 返回 201 `{id, created, kind, signed_in}`，不回显正文。
请求体固定为 `{kind, body, contact, page}`，`page` 是提交时所在的页面地址，
用于定位问题。未知字段、超长内容、控制字符和非法类型一律 422。

## 登录状态

反馈接口对访客开放：`current_user_optional` 只在请求带**有效**令牌时解析
账号，过期或已登出的令牌按「未登录」处理而不是 401——正因如此，登录坏了
也能反馈。账号 ID、账号名和角色全部由服务端从令牌读取，不取自请求体；
未登录的条目在管理员后台显示为「匿名」。提交限流为进程内每来源 10 次/
10 分钟，不持久化 IP。

## 存储与查看

`itp/feedback.py` 在账号库启动时幂等新增 `feedback` 表：
`id TEXT PRIMARY KEY`、`user_id TEXT REFERENCES merchants(id) ON DELETE SET NULL`、
`account_name`、`role`、`kind`、`body`、`contact`、`page`、`created INTEGER`，
并在 `created DESC` 上建索引。账号被删除时历史反馈保留（`user_id` 置空），
正文与联系方式不受影响。

`GET /api/admin/feedback?limit=20&offset=0` 需要管理员令牌，按时间倒序返回
`{total, items}`；顾客与商家令牌得到 403，匿名得到 401。`/admin` 的「用户反馈」
区块显示总数、逐条时间/账号/类型/内容/联系方式/来源页面，支持上一页与下一页
和空状态。该区块**只读**；会员积分赠送与服务配置由各自的管理员区块处理，
反馈内容原样保留提交时的样子。
