# 管理员赠送会员与积分

管理员登录 `/admin` 后，在「会员与积分赠送」搜索正常的顾客或商家账号，核对昵称及完整账号 ID，选择会员套餐和期数，或填写积分额度。填写原因后先预览，再确认赠送。页面提供按时间倒序的赠送记录及分页，展示对象、内容、原因和操作人。

会员套餐按账号身份筛选，只能赠送当前有效、可购买的套餐；免费版、已停用套餐、管理员账号和禁用账号不可赠送。每次赠送 1–12 期，每期长度取套餐配置。已有同套餐会员从当前结束时间继续续期，复用原日历月算法和权益快照。顾客赠送月会员可使用签到、补签等会员权益，但不触发“首次付费会员赠 1000 积分”，也不消耗首次付费奖励资格。

积分额度为 1–1,000,000,000 的整数，通过现有积分钱包及不可修改的积分流水记账，类型为 `admin_gift`。顾客端积分流水显示「管理员赠送」。赠送不会扣人民币钱包余额，也不会生成充值、已支付订单或模拟支付记录。

## 接口

以下接口都要求有效管理员 Bearer 令牌，响应不缓存且不出现在公开 OpenAPI。赠送操作的管理员 ID 从认证身份读取，客户端不能指定。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/admin/gifts?limit=20&offset=0&user_id=...` | 赠送记录、总数及当前可赠送套餐；账号筛选可选 |
| GET | `/api/admin/gifts/accounts?q=...` | 按账号、昵称或完整 ID 搜索；最多返回 20 个有效账号 |
| POST | `/api/admin/gifts` | 原子发放并记录审计信息 |

会员请求示例：

```json
{
  "request_id": "91e9bc1d-6724-42da-9df0-686d28408dd8",
  "user_id": "目标账号ID",
  "kind": "membership",
  "plan_id": "merchant_premium",
  "periods": 1,
  "reason": "活动赠送"
}
```

积分请求将 `kind` 设为 `points` 并提供 `points`，不填写 `plan_id` 与 `periods`。原因不能为空，最长 200 字。未知字段、布尔值、字符串金额、非整数和超限值会拒绝。

同一管理员的 `request_id` 保证幂等：相同内容重试返回原结果，`replayed=true`；编号相同但内容不同返回 409。会员/积分发放和 `admin_gifts` 记录在同一个 SQLite 写事务中完成；失败全部回滚，并发重试只发放一次。审计表通过触发器禁止更新或删除。

前端确认时把待处理请求保存在该管理员的浏览器会话中。网络中断或刷新后可“重试本次赠送”，继续使用原请求编号，避免响应丢失导致重复发放。

## 验证与部署

后端测试覆盖未登录/普通账号/禁用管理员拒绝、非法参数、积分和会员幂等、并发重试、同套餐续期、不触发首次付费奖励、其他账号隔离、事务回滚、搜索隐私和缓存保护。桌面及手机端测试覆盖预览后确认、角色筛选，以及响应丢失后刷新重试。

部署前用 SQLite 在线备份备份 `merchants.sqlite3`，保留服务器 `.env`。应用启动时自动创建 `admin_gifts` 表、索引和审计触发器，不改原有账号和权益。录制演示期间暂缓同步及 API 重启，使用已验证的 Git 提交在录制结束后部署。
