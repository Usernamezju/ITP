# 穿搭推荐

把图生 3D 的比例结果转成成套穿搭。与「人体建模」「虚拟试穿」并列，是工作台左侧导航的第三个入口。推荐逻辑与服装目录完全在本机：分析只读本地 GLB 产物，目录写在 `src/itp/wardrobe.py`，没有任何云服务依赖。每套穿搭会按关键词从**图片检索服务**取真实穿搭照片并缓存在本机，默认使用免 key 的 360 图片，可在设置页切换到 Unsplash 或 Pixabay；取不到图片时自动回落到配色示意图。

## 数据来源与优先级

推荐有两条路径，按下面的顺序取用，页面永远有内容：

1. **商家发布的套装**（`GET /api/looks`，只含 `published`）——按**尺码指标**打分排序，卡片标记「商家」，图片直接用商家上传的商品图。
2. **商家发布的单品**（`GET /api/garments`）——同样按尺码指标打分，一张卡展示一件。
3. **内置 18 套目录**——商家还没发布任何商品时的兜底，沿用标签匹配，`origin` 为 `catalogue`。

尺码匹配的输入来自两处：「人体建模」页选填的身高/体重/肩宽/胸围/腰围/臀围，以及「穿搭推荐」页解析 GLB 得到的比例。指标定义、换算与打分规则见 [指标与匹配规范](METRICS.md)；商家如何导入商品见 [商家接口](MERCHANT.md)。

## 目标与边界

- 有三维模型时，用模型实测的肩宽、腰线、胯宽与腿身比排序；**尚未生成模型时按通用体型推荐**，页面明确显示「尚未生成三维模型」并给出前往人体建模的入口，不阻塞、不报错。
- 只做推荐与展示：不生成图片、不做试穿、不涉及交易与库存。
- 所有体型指标都是**从模型包围盒与轮廓切片估算**的搭配参考，不是人体测量学结论。

## 目录

18 套完整穿搭，覆盖 8 种风格（通勤 / 休闲 / 街头 / 运动 / 度假 / 复古 / 极简 / 学院）、5 种季节、15 种场合。每套包含名称、宣传语、介绍、配色（3–4 色）、4–6 件单品（品类 / 名称 / 颜色 / 搭配说明）、穿着建议、不适合的情况，以及三族体型标签与对应推荐理由。标签词表：

| 族 | 取值 | 含义 |
| --- | --- | --- |
| 骨架 | `slim` / `regular` / `broad` | 窄肩修长 / 比例匀称 / 肩背宽阔 |
| 体量 | `light` / `medium` / `heavy` | 体量轻 / 适中 / 厚实 |
| 比例 | `short-leg` / `balanced-leg` / `long-leg` | 腿身比偏短 / 标准 / 偏长 |

目录顺序即编辑顺序：无模型时所有套装同分，按目录顺序呈现（通勤 → 休闲 → 街头 → 运动 → 度假 → 复古 → 极简 → 学院）。

## 人体分析

`analyze_glb(path)` 直接解析 GLB 二进制容器：校验头部与 chunk，取 `meshes[*].primitives[*].attributes.POSITION` 指向的 accessor（componentType 5126 float32、type VEC3、无 Draco 压缩、非 sparse），用 numpy 一次性解码顶点。

- **轮廓切片**：身高等分为 20 段，自模型顶部向下编号（band 0 为最上 5%，band 19 覆盖足部）。每段取该段顶点的 `(max X - min X) / 身高`。
- **肩宽**：顶部 15%–35% 区间内最宽的一段。宽于第 6–13 段中位数 1.8 倍的段落视为张开的双臂并剔除，因此 T-Pose 模型不会因为手臂水平而被读成「宽阔」。
- **腰宽**：30%–55% 区间内最窄的一段，以 `腰宽 / 肩宽` 呈现。
- **胯宽与腿长比**：50%–70% 区间内最宽的一段，其中点即胯线；腿长比 = `1 - 胯线`。
- **体厚**：Z 跨度 / 身高。同时输出 `体厚 / 体宽` 供参考，但体量族由前者判定：窄肩身体的 `体厚 / 体宽` 偏大，会把「瘦」读成「厚实」，而 `体厚 / 身高` 与姿态无关。

判定阈值（按服装廓形划分，与上面的分带几何对应）：肩宽比 < 0.22 `slim`、< 0.27 `regular`、否则 `broad`；体厚比 < 0.17 `light`、< 0.24 `medium`、否则 `heavy`；腿长比 < 0.375 `short-leg`、< 0.425 `balanced-leg`、否则 `long-leg`。胯窗口把腿长比限制在约 0.33–0.48，因此阈值是这段可达区间的三等分，而不是 0–1 的三等分。

保护与降级：文件 > 512 MiB、声明顶点 > 500 万、Draco、sparse、非 float32/VEC3、accessor 越界、外部或 data URI buffer、容器截断、几何退化 —— 任何一种情况都返回 `null`，接口降级为通用推荐（HTTP 200），不会抛出异常。每个请求把 GLB chunk 读入内存，无缓存；本机单用户工作台足够。

**已知局限**：假设 Y 轴向上（glTF 规范），Z 轴向上的导出会算错且无法自动识别；A-Pose（约 45°）可能没有干净的手臂尖峰，肩宽偏大、骨架可能偏向 `broad`；腿长比受胯窗口限制，数值偏小，不是人体测量学数值。这些限制同时写在模块 docstring 与接口返回的 `notes` 中。

## 打分与排序

基础分 0.30，保证任何条件下都有内容可看。命中标签：骨架 +0.22 > 体量 +0.16 > 比例 +0.10。命中筛选：风格 +0.10、季节 +0.06、场合 +0.06；筛选已设置但未命中则分别 −0.10 / −0.05 / −0.05，**只降权不排除**，因此筛选永远不会得到空列表。分数上限 1.00、下限 0.10，同分保持目录顺序。相同输入永远得到相同输出。

## 穿搭图片

每套穿搭在目录里带一个中文 `image_query`（内部字段，不出现在接口返回里），由它到检索服务取图。三个来源，`ITP_IMAGE_PROVIDER` 选择，未配置对应密钥时自动回落到默认源：

| provider | 密钥 | 说明 |
| --- | --- | --- |
| `so`（默认） | 免 key | 360 图片的公开检索接口，中文关键词相关度高，**唯一经过真实联网验证**的来源 |
| `unsplash` | 需 Access Key | 按官方 API 实现，图片授权清晰；无 key 无法实测 |
| `pixabay` | 需 API Key | 同上 |

取图与缓存（`src/itp/outfit_images.py`）：

- 检索结果里的缩略图由后端**下载到本机**再提供，页面不外链第三方 CDN；单图上限 8 MiB，超过则跳过。文件落在 `data/outfit_images/img/`，元数据落在 `data/outfit_images/meta/`，元数据 7 天过期，图片长期保留。
- 缓存键只含 `provider + 查询词 + 页码`，**不含 `limit`**：内部固定取一整页结果（12 条）存下来，返回时按 `limit` 切片。因此卡片（少量）与详情弹窗（更多）命中同一次检索，不会重复请求源。
- 但**只同步下载本次要用的那几张**，其余候选连同远程地址一起留在元数据里；后续请求要更多张时，命中缓存后**只补下载缺的那几张**。下载在单次请求内部并发（线程池），因此冷启动只需等下自己要看的图，而不是整整一页。
- 单次请求超时 8 秒；失败时返回空列表加一句中文原因（HTTP 仍为 200），并写入 15 分钟负缓存，避免反复探查已被拒绝的源。同一个源的在途请求有并发上限，遇到 429/5xx 短退避重试一次。
- 前端严格**串行**发起图片检索（一次一个，间隔 0.6 秒），卡片进入视口才请求。免 key 的 360 图片在短时间密集请求后会返回「访问异常」页（HTTP 200 + HTML，不是 429），这是该来源的固有风险；此时卡片显示配色示意图并给出「重试」，重试会带 `refresh=true` 绕过负缓存。需要更稳定或授权更清晰的来源，在设置页切换到 Unsplash 或 Pixabay。
- 去重按原图 URL；宽或高小于 200 像素的图被过滤。
- 实测（本机、默认 360 图片）：冷缓存 `limit=4` 约 5 秒返回 4 张；紧接着 `limit=8` 约 2.5 秒（只补下载 4 张）；完全命中缓存 0.15 秒。

**版权与来源**：默认来源是公开网页接口的检索结果，图片版权属于各自的作者与站点，不是授权图库。因此页面为每张图保留**来源链接与原图链接**，在详情弹窗标注「版权归原作者所有」，图片只缓存在本机、不对外分发。需要更明确的授权时，在设置页把 provider 切到 Unsplash 或 Pixabay。

## 接口

`GET /api/outfits`

| 参数 | 说明 |
| --- | --- |
| `job_id` | ITP 任务 id，取其最新的 GLB 产物进行分析 |
| `asset_id` | 直接指定已存储的 GLB 资产；与 `job_id` 同时给出时以 `asset_id` 为准，`job_id` 仍提供姿态与参考图说明 |
| `style` / `season` / `occasion` | 目录中出现的原文筛选值 |
| `limit` | 1–24，默认 6；越界返回 422 |

响应固定四个顶层字段：`source`（`model` / `default`）、`analysis`（`available`、`method`、`labels`、`metrics`、`profile`、`notes`、`tags`，有模型与无模型形状一致）、`filters`（`styles` / `seasons` / `occasions`，各为 `{id, count}`，`count` 是全目录数量、不受当前筛选影响）、`recommendations`（按分数降序，含 `id`、`name`、`tagline`、`story`、`style`、`season`、`occasion`、`palette`、`items`、`tips`、`avoid`、`reason`、`score`、`matched`）。

`GET /api/outfits/{outfit_id}/images?limit=6&page=0&refresh=false`

返回 `outfit_id`、`query`、`provider`、`provider_label`、`cached`、`error`、`images`；每张图含本地 `url`、`original_url`、`source_url`、`site`、`title`、`width`、`height` 以及 Unsplash/Pixabay 才有的 `creator`、`license`。`limit` 1–12、`page` 0–9，越界 422；`outfit_id` 不存在 404；检索失败仍返回 200 与空列表加 `error`。`refresh=true` 绕过缓存重新检索。

`GET /api/outfit-images/{name}`

返回缓存的图片本体，`name` 只接受 40 位十六进制 sha1 加 `.jpg`/`.jpeg`/`.png`/`.webp`，其余一律 404，因此目录穿越与任意文件读取都取不到东西。

## 界面

三栏布局，与虚拟试穿一致。左栏选择分析来源（默认取最近一个含 GLB 产物的任务，可切换或不使用模型）并按风格、季节、场合筛选，筛选为可点选可取消的标签；中栏上半区显示轮廓切片图与肩宽、腰线、胯宽、腿身比指标卡，下半区是按匹配度排序的套装卡片。卡片显示该套的检索照片，右上角在有模型分析时显示匹配度，右下角在有多张图时可「换一张」；**卡片进入视口附近才发起检索**，所以「查看全部套装」到 18 套时不会一次性打满检索源，未取到图的卡片显示配色示意图。点开卡片弹出详情：左侧是图片主图与缩略图条，每张图带标题、站点、来源与原图链接，下方标注版权归属；右侧是介绍、套装单品（颜色取自该套配色）、穿着建议、不适合的情况与本次推荐理由。右栏列出可用于分析的模型、图片检索服务状态与本地服务状态。

无模型时中栏显示通用推荐说明与「前往人体建模」入口，卡片不显示匹配度（此时所有套装同分，展示分数没有意义）。手机视口下改为单列堆叠，右栏隐藏。配色示意图为纯 SVG 绘制，不含人物照片，人形只作服装示意；真实照片一律来自检索服务并保留来源链接。

## 验证

- `tests/test_wardrobe.py`：27 项，覆盖目录完整性、现场合成的 GLB 解析、T-Pose 手臂剔除、9 类非法或损坏 GLB 的降级、打分与筛选、`limit`、确定性，以及 5 组接口测试。
- `tests/test_outfit_images.py`：49 项，覆盖三个 provider 的响应解析与边界、缓存命中与 7 天过期、`refresh` 绕过、负缓存与 429/5xx 重试、去重与小图过滤、超限图片跳过、并发下载不错序、单张失败不影响其余、文件名白名单与目录穿越、`limit` 只切片不重复检索、以及设置页新字段的读写与非法值拒绝。全部离线，不访问网络。
- `frontend/tests/outfits.spec.ts`：5 项，覆盖有模型的分析展示与卡片照片、换一张、详情弹窗的图片与来源链接、无模型时的通用推荐与跳转、检索失败回落到配色示意、筛选与模型来源确实传到接口；桌面与移动两个项目各跑一遍。
- 真实联网验证：默认 360 图片在真实链路上返回了与风格匹配的中文穿搭图（腾讯新闻、网易、百家号等），页面显示、本地缓存、来源链接、路径穿越防护（四种非法文件名全部 404）均实测通过。
- **未验证**：真实云 API 产出的 GLB。仓库内没有真实模型样例，真实图生 3D 需要付费云服务才能产生；分析逻辑只用合成几何与真实接口契约验证过，A-Pose 的肩宽判定尤其需要真实样例校准。Unsplash 与 Pixabay 两个 provider 也因没有密钥而只做了构造响应的单元测试。
