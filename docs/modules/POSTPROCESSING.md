# 拓扑、纹理、绑骨与导出（已下线）

这四项后处理已按修正案整体移除：基础建模只需要一条能产出可预览、可下载 GLB
的最小链路，几何生成一步就返回这样的模型。以下内容保留为记录，说明它们原先
如何工作、接口长什么样——`Pipeline.ACTIONS` 里已不再有它们的动作，请求模型也
不再接受这四个开关（字段仍声明为只能取 false，好让旧客户端得到一句明确的中文
拒绝，而不是看不懂的 422）。

保留的链路是：可选姿势编辑 → 几何生成（`SubmitHunyuanTo3DProJob`）。产物必须是
文件头合法、网格有效的 GLB，否则按失败处理并由既有的失败路径原路退还积分。

## 智能拓扑

`SubmitReduceFaceJob` 接受 GLB/OBJ，面数档位 low/medium/high，面类型 triangle/quadrilateral。四边面选项允许服务端返回混合面，不承诺全四边形。操作可能改变 UV，因此置于纹理之前。首版不将通用三角减面算法冒充智能重拓扑。

## PBR

使用最终几何模型和当前姿势角色图，`EnablePBR=true`。界面默认 2048，API 支持本项目提供的 1024/2048/4096。GLB 中包含的材质由 Three.js 显示；独立贴图仅在供应商返回后保存，不合成虚假材质结果。

## Rig

`SubmitAutoRiggingJob` 输入 GLB/FBX。人形角色要求中性 A/T 姿态，并尽量没有武器、坐骑或复杂配饰。用户必须声明中性姿态；custom 动态姿态与 rig 组合在前后端均禁止。用户声明不等于自动姿态检测。动画播放与重定向不属于当前预览器能力。

## 导出

文件按供应商实际返回格式展示。GLB 可在线预览；OBJ 常带 MTL/纹理，若服务返回 ZIP 则整体下载，不在服务端自动解压。FBX 使用 `Convert3DFormat`，不是修改文件后缀。OBJ 不保留骨骼动画，完整 rig 应优先使用 GLB/FBX。

下载仅接受供应商 HTTPS 域名后缀（myqcloud.com / tencentcos.cn / aliyuncs.com），检查 DNS 不指向私网，逐次检查重定向，默认单产物上限 150 MiB；图像上限 10 MiB。防护适用于当前单机信任边界，公网部署还需要出口网络隔离以强化 DNS 重绑定防护。外部下载失败会让任务失败，不显示虚假的成功状态；之前保存的阶段产物仍可取回。
