# Web 工作台

前端位于 `frontend/`，使用 React、TypeScript、Vite、Three.js。构建资源打包到 `frontend/dist/` 后由 FastAPI 本地提供；运行时不依赖境外 CDN。开发服务器使用 Vite 的本地 `/api` 代理。默认服务仅绑定回环地址。

## 地址与路由

三类界面各有真实地址，用 `react-router-dom` 的 `createBrowserRouter` 管理，可以直接打开、刷新和分享链接：

| 地址 | 界面 |
| --- | --- |
| `/` | 顾客端工作台（人体建模） |
| `/tryon`、`/outfits`、`/history`、`/account`、`/appearance` | 顾客端其余页面 |
| `/merchant` | 商家后台 |
| `/admin` | 系统管理后台（平台运维） |

顾客端五个页面共用一个外壳（左侧导航、顶栏、状态栏）和一份共享状态，因此从工作台切到别的页面再回来，已上传的图片与填写的选项都还在。左侧导航是真正的链接，当前页会被标记。FastAPI 在所有接口之后注册 SPA 兜底路由：命中的构建文件直接返回，其余页面地址返回 `index.html`，`/api/` 前缀仍然 404，`/docs` 与 `/openapi.json` 不受影响；路径解析限制在 `frontend/dist` 内，不会读到目录之外的文件。顾客端未匹配的地址回到工作台。

## 页面与交互

工作台左侧上传角色、姿势、多视角并选择生成步骤；中间显示 GLB 预览与每阶段产物；右侧显示服务配置状态与任务历史。打开资产时，预览标题旁显示该任务的目标面数、姿势模式、拓扑、纹理、绑骨、FBX 导出选项和调用模型。新任务保存创建时的模型版本；旧任务若没有记录版本，页面会明确显示“版本未记录”。客户端不提供模型凭据或接口地址的配置功能，平台运维统一在服务端管理这些配置；客户端仅查询可用状态。任务历史以本机 IndexedDB 里的镜像为主：页面打开时读回本机记录，再把当前账号在服务端尚未清理的任务合并进来，产物下载到本机后才确认删除服务端副本；从未登录过的浏览器不查询服务端。已上传图片显示预览，去背景开关仅影响后续上传。

左侧导航的「穿搭推荐」与人体建模、虚拟试穿并列，用于把三维模型的比例转成成套穿搭。左侧选择分析来源（默认取最近一个含 GLB 产物的任务，可切换其它任务或选择不使用模型），并按风格、季节、场合筛选；中间优先显示推荐商品与套装卡片；模型轮廓、人体参数来源、肩宽、腰线、胯宽、腿身比等信息可展开查看，卡片按推荐分排序，每张卡显示该套的检索图片与配色；点开卡片可浏览更多参考图并查看套装单品、穿着建议、不适合的情况与本次推荐理由，每张图都保留来源与原图链接；右侧列出可用于分析的模型、图片检索服务状态与本地服务状态。图片按单品与风格从检索服务获取并缓存在本机，取不到图片时自动回落到配色示意图。尚无三维模型时按通用体型推荐，并在页面上给出前往人体建模的入口。

「人体建模」页的生成设置里还有一组**选填**的人体数据（身高、体重、肩宽、胸围、腰围、臀围），保存后存在本机浏览器而不是服务器（见 [顾客本地数据与临时计算](PRIVACY.md)）。它们是「穿搭推荐」做尺码匹配的输入：填了身高才能把模型比例换算成厘米，未填项由模型比例推算并在界面上标为「估算」（腰围/臀围由正视图宽度按椭圆周长换算，误差较大，会附警告；胸围模型没有对应比例，只能实测）。推荐结果因此可以逐维度展示「你的数值 / 该款适配区间 / 合身状态 / 中文理由」。

商家侧通过接口导入商品（见 [商家接口](MERCHANT.md)），导入后该套在推荐页会标记「商家」，卡片直接使用商家上传的商品图而不是网络检索图；已发布套装优先于单件，二者都没有时才回落到内置目录。

左侧导航的「商家后台」是给商家上货用的页面，与浏览侧的几个页面并列：未登录时显示注册/登录卡片，登录后顶部显示商家名、账号、联系方式与配额用量（含进度条）以及「账号设置」入口，下面在「我的商品」与「我的套装」之间切换。商品列表逐条给出颜色块或商品图、品类、价格、图片数量和适配区间摘要，可直接编辑、发布、转为草稿或删除；新建与编辑表单分成「基本信息」「尺寸与适配区间」「版型与属性 + 商品图」三段，下拉项、取值范围与长度上限全部来自 `GET /api/garment-options`，越界或区间倒置会就地提示且不发出请求；套装页从已发布的单品里勾选组合，配色默认取成员主色，可先存草稿。登录令牌保存在浏览器本地，刷新不掉线，令牌失效时自动回到登录页。「账号设置」里可以改密码（需要当前密码），改完会立刻退出登录——因为改密即吊销旧令牌，需要拿新密码重新登录一次；忘记密码只能在本机用 `scripts/reset_merchant_password.py` 重置。

`/admin` 是平台开发者维护 ITP 系统的控制台，外壳与顾客端、商家端完全分开，只读、不做任何写操作。未登录时显示管理员登录卡，页面上没有注册入口——管理员账号只能由运维人员在服务器上运行 `scripts/create_admin.py` 创建；已登录但角色不是 `admin` 时显示拒绝卡，且不会向任何 `/api/admin/*` 接口发请求。管理员看到六个分区：**运行状态**（平台版本、3D 生成/姿势编辑/抠图权重的配置情况、FaceVerse 探针的配置与可达性、试穿模型与自建推理服务的可用状态、支付通道）、**模型服务配置**（只读的接口地址与模型名；密钥只显示「已配置/未配置」，凭据由服务器 `.env` 管理，网页不提供填写与保存入口）、**账号与商户**（角色、商品数、上传额度、是否禁用、注册时间）、**平台数据统计**（钱包数量与余额合计、模型扣费与退款、商品与套装数量、订单状态、最近 20 条钱包流水）、**订单与支付**、**服务端任务**（服务端当前保留的建模/试穿/脸部精修任务，并注明顾客确认保存后服务端副本即被删除、没有历史记录）。各分区独立容错，某个接口失败只在该分区显示错误；令牌失效（401）会清掉浏览器里的令牌并回到登录卡。

点击“开始生成”会列出尚缺的角色图、姿势参考图、服务配置或绑骨确认项。已上传图片可点击放大，另有更换与移除按钮。外观页默认采用电商橙，同时保留森林绿、海洋蓝、暖日橙、暮光紫、科技风、少女粉配色和标准、高对比度选项；外观选择只保存在浏览器本地。常见云端错误码显示中文排查建议，同时保留原错误码与 RequestId。

如果未配置云端 API，上传、预处理和本地 GLB 导入可用，生成入口提示“暂不可用”，不引导用户填写密钥。姿势编辑阶段结束后，用户须确认或放弃姿势图。未确认前，3D 阶段不会启动。

Three.js 预览只接受自包含 GLB。导入用户文件或服务返回的 GLB 后自动居中、归一化尺寸，支持旋转、缩放、线框视图。OBJ、FBX、ZIP 均提供真实文件下载，当前预览器不解析这些格式；附加外部纹理引用、Draco 等压缩扩展也未实现。

前端每 3 秒刷新一次任务列表——先读本机记录，已登录时再合并服务端尚未清理的任务，页面关闭后停止定时器。较大模型载入、WebGL 不可用和格式错误会给出提示；模型场景与 GPU 资源在组件卸载时释放。空白场景中的线框立方体仅为视觉指示，不表示生成了模型。

## 构建与测试

前端锁文件 `package-lock.json` 固定安装版本，`npm ci` 用于复现；`npm run build` 会先进行 TypeScript 检查。Playwright 在桌面和手机视口覆盖未配置状态、图片上传、姿势模式切换、本地 GLB 导入、任务历史和外观页，并断言不存在密钥表单或服务配置请求。`tests/routing.spec.ts` 逐个打开并刷新每个顾客端地址、检查导航是真实链接、确认切页后工作台输入仍在，并验证顾客打开 `/merchant` 会被拒绝；`tests/admin.spec.ts` 覆盖登录卡没有注册入口且未登录时不请求管理接口、管理员登录后六个分区都有数据、顾客被拒绝且零次请求、401 自动回到登录卡、配置分区只有只读文本（没有输入框与保存按钮）以及单个分区失败不影响其它分区。后端 `tests/test_spa.py` 用假构建目录断言每个地址返回应用、`/api` 与穿越路径不会被兜底路由接走，以及没有构建产物时只回答接口。真实任务审核与产物下载仍需云端账号联调。

密钥由平台运维配置于服务端 `.env` 或进程环境变量，网页不接收、不发送、不保存模型 API 密钥或服务 token。浏览器保留的登录令牌是用户账号认证，不是模型服务凭据。工作台是本机单用户应用；外网部署需要认证、配额、隔离和新的跨域策略。


## 电商视觉规范与人工验收

本轮遵循仓库 [taobao-commerce-ui Skill](../../.codex/skills/taobao-commerce-ui/SKILL.md)，
继续使用 React 19、普通 CSS 与 lucide-react，无新增组件库。路由、左侧导航、
人体建模三栏 Grid 与虚拟试穿流程保持原有结构；默认主题由森林绿切为电商橙，
已主动保存的其它主题继续有效，外观选项仍仅保存在浏览器。

`styles.css` 集中定义 `--commerce-*`：大面积背景 `#F5F5F5`、白色卡片、
深灰正文、橙色 `#FF5000` 品牌强调。橙色用于价格、购买入口、主要操作与
选中标签，不铺满导航和页面。14px 白字按钮使用更深的 `#D94200`
（`--commerce-action`），hover 为 `#C43D00`，保证正文大小按钮的文字对比度；
小号橙色文本使用 `--commerce-primary-text: #C43D00`。成功、处理中和失败
使用独立语义色并保留文字，交易状态不依赖颜色辨认。

字体采用 system-ui、苹方、微软雅黑、Noto Sans CJK SC；普通正文与主要按钮
14px、辅助文字12px、区块标题16–18px。商品图保持固定比例，不拉伸；名称、
推荐理由限制两行，价格和购买按钮突出，尺码与模型来源保留在可展开区域。
商家点击概览先展示今日、本月、累计三个 KPI，商品表格和14日趋势只在各自
容器内滚动，小屏 KPI 自动折行。钱包余额、充值与状态复用资金模块样式。
焦点 outline、键盘导航、禁用和 loading 状态继续保留，并尊重 reduced motion。

本轮验收命令（项目根目录）：

```bash
npm run build --prefix frontend
npm run test:e2e --prefix frontend
# 浏览器缓存使用默认 ~/.cache/ms-playwright；若使用其它路径，需先在该路径安装 Chromium。
```

人工浏览器检查至少使用1440×900与412×915视口，逐个打开首页、`/outfits`、
`/merchant`、`/account` 和 `/tryon`：确认页面无横向溢出、侧栏不遮挡内容，
图片比例正常、商品名/理由/价格/购买入口层级清晰，展开算法信息可阅读，
商家三个KPI及商品表格可查看，余额和充值可见。用 Tab 浏览链接、按钮、
输入框及 details，检查焦点；切换高对比度和其它主题后刷新检查选择持久化。
登录和支付验收方法分别见 [ACCOUNTS.md](ACCOUNTS.md)、[COMMERCE.md](COMMERCE.md)
与 [PAYMENTS.md](PAYMENTS.md)。
