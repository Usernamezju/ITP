# 指标与匹配规范

穿搭推荐从「标签匹配」升级为「指标匹配」：人体与服装各自量化成一组带单位与区间的指标，再由 `src/itp/size_match.py` 逐维度打分并给出可解释理由。本文档是这两组指标与打分规则的**权威定义**；接口字段见 [MERCHANT.md](MERCHANT.md)（服装导入）与 [OUTFITS.md](OUTFITS.md)（推荐）。

## 1. 两个量化对象

| | 人体指标 | 服装指标 |
| --- | --- | --- |
| 采集位置 | 「人体建模」页的生成设置里，**全部选填** | 商家客户端接口导入 |
| 权威来源 | 用户实测优先，模型比例补缺 | 商家填写的实测/标称值 |
| 存储 | `body_profiles` 表（可按任务区分，也可只存默认档案） | `garments.metrics`（JSON） |
| 用于 | 与服装的适配区间逐维度比对 | 提供适配区间与属性 |

## 2. 人体指标

| 字段 | 单位 | 边界 | 说明 |
| --- | --- | --- | --- |
| `height_cm` | cm | 120–220 | **换算的前提**：只有填了身高，模型比例才能折成厘米 |
| `weight_kg` | kg | 30–200 | 只作为参考信息，不参与维度比对 |
| `shoulder_cm` | cm | 25–70 | 肩宽 |
| `bust_cm` | cm | 60–160 | 胸围（围度） |
| `waist_cm` | cm | 45–150 | 腰围（围度） |
| `hip_cm` | cm | 60–170 | 臀围（围度） |

每个维度都带 `{value, source, confidence}`，其中 `source` 只有三种取值，界面据此显示不同标签：

| source | confidence | 界面标签 | 含义 |
| --- | --- | --- | --- |
| `input` | 1.0 | 已填 | 用户实测 |
| `estimated` | 0.7（直接比例）／0.3（宽度换算） | 估算 | 由 GLB 分析推算 |
| `missing` | 0.0 | 未填 | 无数据，不参与打分 |

### 2.1 从 GLB 推算的两条路径与一个陷阱

GLB 分析给的是**正视图轮廓**：`shoulder_ratio`（肩宽/身高）、`waist_ratio`（腰宽/肩宽）、`hip_ratio`（臀宽/肩宽）、`leg_ratio`、`thickness_ratio`。

- **肩宽可以直接乘**：`height_cm × shoulder_ratio`，170cm 参考体得 37.9cm，量级正确。
- **腰围/臀围不能直接乘**：轮廓给的是**宽度**，而服装区间是**围度**。直接相乘会得到「臀围 34.9cm」这种荒唐值，结果所有下装都被判成严重偏紧。因此先按椭圆周长（Ramanujan 近似）把宽度换算成围度，躯干截面深宽比取常量 `TORSO_DEPTH_TO_WIDTH = 0.75`；170cm 参考体得腰围 77.5cm、臀围 96.3cm，与常人相符。换算维度按**最低置信度 0.3** 处理，并强制给出一条「由模型轮廓宽度换算，误差较大，建议实测」的警告。
- **胸围永不估算**：模型没有对应比例，只有用户实测才有值；缺失时该维度记为 `unknown` 并不参与打分。
- 假设 Y 轴向上（glTF 规范）；Z-up 导出会算错。

### 2.2 决策记录

**换算得到的腰围/臀围参与打分**（而不是当作缺失）。理由：产品主流程是「上传图片 → 生成 3D → 看推荐」，多数用户不会量体；若把它们当缺失，主流程几乎只剩肩宽一个维度，指标匹配就名存实亡。代价是围度可能有约一个尺码的误差，用三件事控制：最低置信度、总分向中性收缩、界面同时显示「估算」标签与「建议实测」的警告。

## 3. 服装指标

**尺寸类（cm，实测或标称平铺值，全部可空）**：`shoulder_cm`、`bust_cm`、`waist_cm`、`hip_cm`、`length_cm`、`hem_cm`。取值必须 > 0 且 ≤ 300。

**适配区间（`[min, max]`，单位 cm，`min <= max`）**：

| 键 | 边界 | 说明 |
| --- | --- | --- |
| `height_cm` | 120–220 | 适合身高 |
| `bust_cm` | 60–160 | 适合胸围 |
| `waist_cm` | 45–150 | 适合腰围 |
| `hip_cm` | 60–170 | 适合臀围 |
| `shoulder_cm` | 25–70 | 适合肩宽 |

**属性类**：

| 键 | 取值 | 用途 |
| --- | --- | --- |
| `silhouette` | 修身 / 标准 / 宽松 / oversize | 与体型标签相互作用 |
| `stretch` | 无弹 / 微弹 / 高弹 | 偏紧时的缓解程度 |
| `weight_gsm` | 20–2000 | 与用户克重偏好比对 |
| `color` | `#rrggbb` | 与偏好色算 CIE76 ΔE |
| `length_type` | 短款 / 常规 / 长款 | 与腿身比相互作用 |

**适配区间是打分的核心**：服装给出「适合谁穿」，人体给出「我是谁」，两者比对即可得到合身度，且天然可解释。

## 4. 匹配算法（`src/itp/size_match.py`）

### 4.1 维度权重与区间打分

权重（归一化后使用）： **胸围 0.28 > 肩宽 0.24 > 腰围 0.18 > 臀围 0.16 > 身高 0.14**，其它维度 0.08。缺失维度不参与并**重新归一化**，因此数据缺失不会凭空拉低合身度。

- 命中区间：区间中心 1.0、边界 0.85，线性内插。
- 越界衰减：`tolerance = max(2cm, 区间宽度 × 0.5)`，`score = max(0, 0.85 × (1 − |超出量| / tolerance))`，在边界处与命中分连续。
- 状态：`fit`（区间内）／`tight`（小于下界）／`loose`（大于上界）／`unknown`（无数据）。

### 4.2 总分、置信度与收缩

- 偏好以**居中调整**进入：`raw = fit_score + 0.30 × (preference_score − 0.5)`。偏好中性值 0.5，所以「没给偏好」时总分恰好等于合身度，命中偏好最多 +0.15、冲突最多 −0.12，且对合身度严格单调。
- 再按置信度向中性收缩：`factor = 0.30 + 0.70 × confidence`，`score = 0.5 + (raw − 0.5) × factor`。置信度越低越接近 0.5，避免「什么都不知道却给 0.95」。
- 置信度：被该款约束且人体有值的维度按权重加权平均，再乘 `(1 − 0.5 × 缺失比例)`。输入 1.0、直接估算 0.7、换算估算 0.3、缺失 0.0。

分数标尺（有测试断言）：全部落在区间正中 **0.99**；全部落在边界 **0.85**；完全不合 **0.00**；只有模型数据时合身度 0.96 被收缩为最终 **0.80**。

### 4.3 体型与属性的相互作用

`build=broad` × 宽松/oversize **+0.06**，× 修身 **−0.08**；`build=slim` × 修身/标准 **+0.04**，× oversize **−0.05**；`volume=heavy` × 宽松/oversize **+0.03**，× 修身且无弹 **−0.07**；`volume=light` × 宽松/oversize **−0.03**；`legs=long-leg` × 长款 **−0.03**；`legs=short-leg` × 短款 **+0.04**，× 长款 **−0.02**。每条都会转成一句带数值的中文理由。

用户偏好信号：版型命中 +0.25 / 冲突 −0.15；弹力 +0.15 / −0.10；克重区间内 +0.10 / 区间外 −0.08；颜色相近 +0.15（ΔE ≤ 12）/ 相差大 −0.12（ΔE ≥ 30）；`avoid_colors` 相近 −0.35。

### 4.4 套装聚合

套装分数 = 成员单品分数的**分类加权**：外套 0.30 > 上装 0.28 > 下装 0.26 > 鞋履 0.08 = 配饰 0.08；缺失分类不参与、不惩罚。套装的适配区间由成员区间求**交集**；交集为空时取「最紧下界…最松上界」并给出一条「成员单品的适配区间不一致」的警告。套装层**不再做第二次置信度收缩**（成员分已各自收缩过，重复惩罚同一份数据缺失是不合理的）。

## 5. 输出与可解释性

`score_garment` / `score_look` 返回 `score`、`fit_score`、`preference_score`、`confidence`、`dimensions[]`、`reasons[]`、`warnings[]`、`suggestions[]`。每个维度给出你方数值（含来源）、该款区间、状态、带符号的超出量与一句中文说明，例如：

> 胸围 88cm 落在该款适配区间 88–100cm 内，位于区间下沿，修身版型会更贴合
> 估算肩宽 37.4cm 超出适配区间 0.4cm，落肩结构可缓解 · 偏紧

界面据此渲染「尺码匹配」表：逐维度对比 + 警告 + 理由 + 匹配可信度。**推荐不再只有分数与标签。**

## 6. 局限

- 所有模型推算值都是**估算**：轮廓宽度换算围度依赖一个固定的深宽比常量，误差可能到一个尺码；界面与接口都标注来源，产品文案不得表述为实测。
- 阈值与权重是按**服装廓形**选的工程值，不是人体测量学或服装工业标准的结论，没有用真实人体样本校准过。
- 服装侧指标完全取决于商家填写的准确性；接口做的是**取值范围与一致性校验**，无法验证数值是否真实测量所得。
